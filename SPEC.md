# ТЗ: AI-бот поддержки с RAG (демо для портфолио)

## Цель
Бот отвечает клиентам на вопросы по базе знаний компании: на сайте (виджет) и в Telegram.
Отвечает только по документам, показывает источники, а если не знает — передаёт вопрос оператору.

Это демо для портфолио Upwork: должно работать вживую по ссылке и хорошо смотреться в видео на 1 минуту.

## Демо-компания
Вымышленная компания **BoxHub Self-Storage** (аренда складских боксов). Не использовать реальные бренды.
База знаний — 5–8 сгенерированных документов: FAQ, тарифы, правила хранения, доступ на территорию, оплата и просрочки, контакты.
Лежат в `data/kb/` (Markdown + один PDF, чтобы показать загрузку PDF).

## Функции (MVP)

### 1. Загрузка базы знаний
- Источники: Markdown/TXT, PDF, URL страницы сайта.
- Разбивка на чанки, эмбеддинги, хранение в PostgreSQL + pgvector.
- Команда CLI: `uv run kb ingest data/kb/` и загрузка файла через админку.
- Повторная загрузка того же документа не создаёт дублей (по хешу содержимого).

### 2. Ответы (ядро)
- `POST /api/chat` — вопрос + `session_id`, ответ стримится (SSE).
- Поиск топ-N чанков по вектору, ответ LLM строго по найденному контексту.
- В ответе — источники (название документа).
- Учёт истории диалога (последние несколько сообщений в рамках сессии).
- Если релевантных чанков нет или модель не уверена — ответ «Не нашёл ответа, передал вопрос оператору» + handoff.

### 3. Передача оператору (handoff)
- Вопрос без ответа отправляется в Telegram-чат оператора (ID чата из `.env`) со ссылкой на диалог.
- Помечается в БД как `unanswered`.

### 4. Виджет для сайта
- Один JS-файл: `<script src=".../widget.js"></script>` — появляется кнопка чата в углу.
- Стриминг ответа, источники под ответом. Минимальный приятный дизайн.
- Демо-страница BoxHub на `/` с подключённым виджетом.

### 5. Telegram-бот
- aiogram 3, тот же backend (общая логика ответа, без дублирования).
- `/start` с приветствием и примерами вопросов.

### 6. Админка
- `/admin` под basic auth (логин/пароль из `.env`).
- Список документов + загрузка нового.
- Лог диалогов: вопрос, ответ, источники, время.
- Отдельная вкладка «Без ответа» — главное для продажи клиенту.
- Простая статистика: всего вопросов, % без ответа.

## Не делаем (вне MVP)
Мультитенантность, регистрация пользователей, оплата, сложный фронтенд-фреймворк.

## Нефункциональные требования
- Python 3.12, uv, FastAPI, PostgreSQL + pgvector (SQLAlchemy async + Alembic), Redis, aiogram 3.
- LLM: Claude через Anthropic SDK, модель в `.env`.
- Эмбеддинги: локально через fastembed (мультиязычная модель, без отдельного API-ключа); провайдер за интерфейсом, чтобы можно было заменить.
- Учёт токенов и стоимости в $ на каждый ответ (показывается в админке).
- Запуск одной командой: `docker compose up`.
- Все секреты в `.env`, есть `.env.example`.
- Тесты на ядро (чанкинг, поиск, логика handoff) — pytest.
- README на английском: что это, скриншот/GIF, как запустить, архитектура в 5 строк.
- Деплой на VPS с HTTPS (Caddy).

## Этапы и критерии готовности

| # | Этап | Готово, когда |
|---|------|---------------|
| 1 | Каркас: uv, FastAPI, Postgres+pgvector, docker compose, Alembic | `docker compose up` поднимает API, `/health` отвечает |
| 2 | Загрузка базы знаний | `kb ingest` загружает `data/kb/`, чанки с эмбеддингами в БД |
| 3 | Ядро ответов | `/api/chat` стримит ответ с источниками; на вопрос не по теме — handoff |
| 4 | Виджет + демо-страница | на `/` можно поговорить с ботом |
| 5 | Telegram-бот + handoff оператору | бот отвечает, вопросы без ответа приходят оператору |
| 6 | Админка | видны документы, диалоги, «без ответа», статистика |
| 7 | Деплой + README + видео | живая ссылка, README, видео на 1 минуту |
